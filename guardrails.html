How goa Radar would run safely inside goa.

1. Human approval before any send

The AI only drafts. Every email, proposal and follow-up sits in a review queue; a named rep must edit/approve it. No auto-send, no bulk send. Approvals are logged (who, when, what changed).

2. Citations required

A trigger can't enter the feed without a public source URL, and every pitch must reference it. Items with dead links or no source are dropped. The chat answers only from the feed and cites trigger ids.

3. Spam Act 2003 compliance

Commercial emails need consent (express, or inferred e.g. conspicuously published business address relevant to the offer), must clearly identify goa as the sender with contact details, and include a working unsubscribe honoured within 5 business days. Opt-outs sync to a suppression list checked before any draft is created.

4. No client data leaves goa systems

Public signals come in; client/CRM data stays in goa's Microsoft 365 / Salesforce tenancy. Production AI calls would use an enterprise endpoint with no training on inputs, logging in goa's tenancy, and only public trigger text + approved templates in prompts. Australian Privacy Principles apply.

5. Salesforce connection

Triggers create Leads/Tasks via the Salesforce API (connected app, OAuth, least-privilege integration user). Dedupe against existing Accounts first; approved emails log as Activities; stage changes feed the weekly digest.

6. Microsoft 365 connection

Drafts land in the rep's Outlook Drafts via Microsoft Graph (delegated permissions, Entra ID SSO). Reps send from Outlook themselves. Digest posts to a Teams channel. Power Automate can schedule the weekly run.

7. Source hygiene

Only public sources used respectfully (council, government registers, news). Robots/terms respected; no scraping of logged-in or personal data.

8. This demo

Unofficial; not built with any goa data except the public site locator. Pipeline digest uses clearly labelled sample data. No emails are sent from this site.
